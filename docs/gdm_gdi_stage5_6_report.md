# ГДМ, адаптация по ГДИ: этапы 5–6, запуск tNavigator и автоцикл (2026-11-14)

## Что сделано
- **Этап 5, запуск.** `case_build.py` строит рабочую папку тестового прогона из любой модели: пути INCLUDE в копии абсолютные (оригинал только читается), расписание обрезается на дате ГДИ (include до неё сохраняются, include после убираются), в SUMMARY попадают только нужные векторы, соединения запрашиваются записью на скважину. Копируется только папка RESULTS (один раз, с проверкой свободного места). `tnav_run.py`: команда `--no-gui --auto-run --auto-exit --ignore-lock --restart=N --ecl-rsm --ecl-root` (Windows и РЕД ОС), фоновая задача с журналом, шагом, отменой с убийством всего дерева процессов и проверкой, что новый RSM появился. Без `--ecl-root` RSM уходит в RESULTS/<имя>/, а не рядом с .data.
- **Этап 6, автоцикл.** `autoloop.py`: итерация 0 без мультов (из неё снимок для обычной адаптации ГДМ), итерация 1 с мультами по формуле ГДМ, дальше уточнение по измеренной в модели депрессии методом секущих (шаг ограничен, D остаётся от подбора), скважина в пределах порога замораживается. Стоп: все в пороге, лимит, нет улучшения, кнопка «Остановить». Каждая итерация пишется в `loop.json`; откат на любую итерацию записывает include и журнал мультов. В интерфейсе шаг 7 вкладки «Адаптация по ГДИ»: настройки, пуск и остановка, сводка по скважинам, таблица итераций, графики на общем ядре графиков.

## Проверка на реальной модели (оригинал только читался; tNavigator 21.3, рестарт с шага 1479)
Три скважины, ГДИ 14.01.2014, порог 10 %, 2 прогона с мультами (≈1,5 мин каждый). Ошибка депрессии по режимам ГДИ, %:

| Скв. | без мультов | итерация 1 (формула ГДМ) | итерация 2 (по прогону) | WPIMULT итог |
|---|---|---|---|---|
| 1 | 584.4 | 16.6 | 1.2 | 2.189 |
| 2 | 65.2 | 3.4 | 3.4 | 0.152 |
| 3 | 11.6 | 11.9 | 7.5 | 1.300 |

Цикл остановился по порогу на второй итерации. Скв. 3 осталась выше нуля из-за Pпл модели ниже ГДИ на 6–7 бар (см. отчёт этапа 4).

## Ограничения
- Один цикл ведётся по одной дате ГДИ; скважины с другой датой запускаются отдельным циклом.
- Шаг рестарта задаётся вручную (номер шага в списке шагов расчёта).
- Расписание прямо в .data (без include) и DATES вне include не поддерживаются: понятная ошибка.

## Очередь по датам (800 исследований)
`AutoBatch`: даты по очереди, строго по одному прогону (параллельные запуски не делаются). Порядок от поздних дат к ранним: рестарт с шага D перезаписывает результаты рабочей копии после D, ранние шаги остаются целыми. Шаг рестарта берётся из журнала расчёта исходной модели (`RESULTS/<имя>.job.log`: «ОТЧЁТ N … ДЕНЬ …»), без ручного ввода. Состояние пишется в `batch.json` (после остановки очередь продолжается с первой невыполненной даты). С готовыми снимками из комплекта базовый прогон на дату не нужен, а скважины, у которых формула ГДМ уже обещает ошибку в пределах порога, можно принять без прогона модели.

Проверка на реальной модели, свежая рабочая копия (копирование RESULTS 3 мин, 36 ГБ), две даты ГДИ: 04.02.2015 (скв. 2: ошибка 2,6 %, 2 прогона) и затем 14.01.2014 (скв. 1 и 3: 1,2 % и 7,5 %, 3 прогона). Вся очередь 6 минут. Размер рабочей папки после очереди не вырос (35,97 ГБ). Опция отключения записи restart (`RPTRST 'BASIC=0'`, `light_output`) убрана: после прогона с ней рабочая копия RESULTS перестала читаться для рестарта, и tNavigator начал считать модель с 1978 года (часы). Теперь прогон дополнительно сам останавливается, если через минуту в журнале нет чтения шага рестарта.

## Версии tNavigator (19.1 … 26.x)
- Пакетный запуск: набор ключей определяется по `--help` и `--full-help` самой версии (`tnav_run.probe`, работает без лицензии). Проверено на 19.1 и 21.3: `--no-gui --auto-run --auto-exit --ignore-lock --restart --ecl-rsm --ecl-root` есть в обеих. Ключ, которого нет в версии, не ставится, при нехватке обязательных выдаётся понятная ошибка. Версия пишется в состояние очереди.
- Код для калькулятора графиков (внутри tNavigator): встроенный Python в 19.1 — 3.5 (python35.zip), в 21.3 — 3.6, в новых — выше. Модули комплекта разбираются Python 3.5: без f-строк, аннотаций переменных, подчёркиваний в числах, dataclasses и `from __future__ import annotations` (тест `tests/test_gdi_adapt_old_python.py`). Чтение шага на дату и признака «перфорация открыта» переносит различия версий API. Не проверено на живом tNavigator 19 и 26: если в какой-то версии калькулятор называет объекты иначе, run.log покажет список имён. Расчёт через тестовый прогон (RSM) от калькулятора не зависит и работает во всех версиях, где есть перечисленные ключи.
