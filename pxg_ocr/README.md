# Распознавание (OCR)

Русский веб-интерфейс к локальному MinerU: загрузка сканов (PDF, изображения, Word, Excel, PowerPoint), выбор качества и режима вычислений, ход работы, просмотр страницы исходника рядом с markdown / JSON, скачивание. Выбор файлов и сохранение — общий проводник (`pxg_core/fs_browse.py`).

Запуск: `Raspoznavanie.bat` / `bash raspoznavanie.sh`, из исходников `python -m pxg_ocr` (`--browser`, `--server [порт]`, по умолчанию 8770).

## Движок
Папка `ocr` рядом с программой (или `PXG_OCR_HOME`, на Windows запасной вариант `C:\OCR`): `python` (или `mineru-env`) с MinerU 4.1.7 и `mineru-home` с моделями tier standard. Устанавливать ничего не нужно, интернет не нужен. Запуск: `mineru-kit parse файл -o результат.zip -f zip --tier standard --ocr-mode ocr`; в zip лежат markdown, JSON и картинки.

Русский текст читает только tier **standard**; basic и flash кириллицу теряют.

## Режимы и память
- «Авто»: видеокарта NVIDIA, если свободно ≥ 7 ГБ (лимит `MINERU_VIRTUAL_VRAM_SIZE` = свободно − 2 ГБ, не больше 6); иначе процессор.
- «Только процессор» (`MINERU_DEVICE_MODE=cpu` и др.): видеопамять не нужна, ошибок памяти нет, ~4× медленнее. Для слабых карт (1050 Ti, 1650).
- Потоков процессора — половина ядер.
- Файлы обрабатываются по одному: распознавание занимает весь ПК.
- Результаты: `<проект>/OCR/<дата>_<имя>/` (markdown, JSON, картинки, meta.json); история — список этих папок. Удаление результата только по подтверждению.

## Собрать БД
Кнопка «Собрать БД» (или `python -m pxg_ocr.extract markdown.md -o база.xlsx`) превращает распознанный markdown в маленькую базу xlsx: акты КРС (+закачки кислоты), заключения ГИС (забой по доходу прибора для шаблонирования, ГВК по датам, Кг по интервалам, комплекс ГИС), отчёты ГДИ (режимы, результаты, перфорация). Вид документа определяется сам; в каждой строке столбец «Проверка» (рукописное — сверять со сканом обязательно).

Тесты: `python -m pytest -q tests/test_pxg_ocr.py tests/test_pxg_ocr_extract.py` (движок подменяется заглушкой). Проверка на реальных сканах — вручную.

## Выгрузка в Word и xlsx
- «Скачать Word» — прочитанный файл целиком в `.docx` (заголовки, абзацы, таблицы с объединёнными ячейками, картинки), Word-документ собирается без сторонних библиотек.
- «Таблицы в xlsx» — таблицы одного файла: лист на тип таблицы (комплекс ГИС, термобарика, заполнение ствола, интервалы Кг, история ГВК, прочие по одинаковой шапке), в строках «Скважина», «Дата», «Файл», «№ таблицы».
- «Сводка таблиц» — то же по многим файлам: из всех готовых результатов или из папки (`*.ocr.md` пакетного прогона, `content_list.json`). Одинаковые типы лежат на одном листе. Листы «Оглавление» и «Файлы» показывают, что собрано и что не найдено в шапке (скважина, дата) — решает инженер.
- Хранение: каждый результат — папка `<проект>/OCR/<дата>_<имя>/` (markdown, JSON, картинки, `meta.json`); сами не удаляются, только кнопкой «Удалить» с подтверждением. Сводки лежат в `OCR/Сводные/`.

## Какой путь выбрать: скрипт или OCR

OCR медленный (десятки секунд на файл), а Word и PDF с текстовым слоем сборщики БД читают напрямую. У каждого выбранного файла программа показывает путь и причину: Word, PDF с текстом на всех страницах — «Скриптом»; сканы, PDF без текста или с текстом не на всех страницах (целиком) и картинки — «OCR». Путь можно сменить вручную у каждого файла (решение инженера главнее). Кнопка «Распознать» берёт только файлы с путём OCR.

Пакетный прогон по папкам: `python -m pxg_ocr.batch ПАПКА ... --out ПАПКА_OCR --mode gpu` (`--dry-run` — только план, `--force-ocr`/`--force-script` — ручной выбор). Сканы идут по одному, markdown лежит в `ПАПКА_OCR/<имя>.ocr.md` (его находят «БД ГИС из отчётов» и «БД шаблонирования»), готовые файлы повторно не считаются, план — `route_plan.csv`.
