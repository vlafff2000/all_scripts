# База ПХГ

Сбор и очистка данных по ПХГ: расходы (отбор/закачка), уровни и давления, межколонные давления, вспомогательные таблицы.
Результат этих модулей — таблицы, из которых читают остальные приложения (Atlas 6, «Схедул ТР», «ГИС и ГВК»).

Запуск (Python 3.9+): из корня репозитория `python -m pxg_base` — меню модулей; либо `python -m pxg_base <номер или имя>`.
Список модулей и описания — в `registry.py`.

Скрипты в `modules/` перенесены без изменения кода (это первый шаг). Дальше: вынести общие функции (поиск строки заголовка,
номер скважины, русские месяцы, сезоны, выбор файла) в общий пакет `pxg_core` и заменить окна tkinter параметрами.

## Веб-интерфейс

Тот же стек, что у Атласа 6: ядро на Python (Starlette) и интерфейс на React + TypeScript.

```
python -m pxg_base --server          # http://127.0.0.1:8766
cd pxg_base/web && npm install && npm run dev    # разработка, /api проксируется на 8766
npm run build                        # пересобрать pxg_base/web/dist перед коммитом
```

Нужны библиотеки из `requirements.txt` (берутся последние версии).

Как это устроено: скрипты консольные и задают вопросы через `input()`. Для веб-запуска в `webspec.py` описаны поля формы и порядок
ответов; сервер запускает скрипт подпроцессом в папке результатов, подаёт ответы на ввод, собирает журнал и список созданных файлов
(`jobs.py`). Код скриптов не меняется. Модуль без описания в `webspec.py` в интерфейсе помечен «консоль» и запускается через меню.

Подключено: «создание_БД_расходов», «нулевой_расход». Чтобы подключить другой, добавьте `WebSpec` в `webspec.py`.
Модули с окнами tkinter (выбор файла через диалог) сначала переводятся на параметры.

## Переносная сборка (без установки, без интернета)

Как у Газового атласа: архив со своим Python 3.14 (с tkinter) и последними версиями библиотек; Python и библиотеки, установленные на компьютере, не используются.
Распаковать и запустить `PXG_Base.bat` (Windows 10 и новее, 64-bit) или `pxg_base.sh` (Linux x86_64, glibc 2.28+: РЕД ОС 8, Astra 1.7 и новее). Открывается окно приложения (Windows, Edge WebView2) или браузер; отдельный сервер
запускать не нужно. `PXG_Base_console.bat` / `pxg_base_console.sh` — консольное меню модулей. Результаты — в папке `pxg_runs` рядом.

Сборка (нужны интернет и Python 3.9+): `python tools/build_portable.py windows|linux` → `dist/PXG_Base_portable_*`.
CI собирает архивы по запросу: Actions → «Portable archives» → Run workflow; он же запускает программу из распакованного архива
на сгенерированных исходниках. Пакеты — последние версии из `requirements.txt` на момент сборки; зафиксировать набор можно через `pip freeze` из распакованной папки.

## Тестовые исходники

`pxg_base/testdata/flows.py` строит файлы в формате, который ждут модули расходов: папки `Отбор/<сезон>/…` и `Закачка/<год>/…`,
книги по месяцам с таблицей часового расхода и таблицей времени работы, файл периодов. В данные намеренно внесены несоответствия
«расход / время», список возвращается в манифесте. `python -m pxg_base.testdata.flows <папка>` создаёт набор вручную.
`tests/test_pxg_flows.py` запускает «создание_БД_расходов» и «нулевой_расход» на этих данных (как из веб-интерфейса) и сверяет
число строк, фильтрацию по периодам и найденные несоответствия с манифестом. Тесты проходят на последних версиях (pandas 3) и на pandas 2.
