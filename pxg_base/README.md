# Работа с исходными данными

Сбор и очистка данных по ПХГ: расходы (отбор/закачка), уровни и давления, межколонные давления, вспомогательные таблицы.
Результат этих модулей — таблицы, из которых читают остальные приложения (Atlas 6, «ГДМ», «ГИС и ГВК»).

Запуск (Python 3.13): из корня репозитория `python -m pxg_base` — меню модулей; либо `python -m pxg_base <номер или имя>`.
Список модулей и описания — в `registry.py`.

Скрипты в `modules/` перенесены без изменения кода (это первый шаг). Дальше: вынести общие функции (поиск строки заголовка,
номер скважины, русские месяцы, сезоны, выбор файла) в общий пакет `pxg_core` и заменить окна tkinter параметрами.

## Веб-интерфейс

Тот же стек, что у Атласа 6: ядро на Python (Starlette) и интерфейс на React + TypeScript.

```
python -m pxg_base --server          # http://127.0.0.1:8766
cd pxg_base/web && npm install && npm run dev    # разработка, /api проксируется на 8766
npm run build                        # пересобрать pxg_base/web/dist перед коммитом
```

Нужны библиотеки из `requirements.txt` (берутся последние версии).

Как это устроено: скрипты консольные и задают вопросы через `input()`. Для веб-запуска в `webspec.py` описаны поля формы и порядок
ответов; сервер запускает скрипт подпроцессом в папке результатов, подаёт ответы на ввод, собирает журнал и список созданных файлов
(`jobs.py`). Код скриптов не меняется. Модуль без описания в `webspec.py` в интерфейсе помечен «консоль» и запускается через меню.

Подключены все модули (в том числе «База ГИС»). Чтобы подключить новый, добавьте `WebSpec` в `webspec.py`.
Модули с окнами tkinter (выбор файла через диалог) сначала переводятся на параметры.

## Нормировка базы расходов на ПЗРГ

Модуль «Нормировка базы расходов на ПЗРГ» (раздел «Расходы») делает копию базы расходов, в которой суммы скважин за сутки равны суточному
объёму коммерческого узла учёта. Основной столбец «Суточный расход газа» нормирован (его читают Атлас, Карты и schedule), исходное значение лежит
в «Суточный расход газа (исходный)», рядом коэффициент и статус строки; журнал и невязка по суткам — в «Журнал_нормировки_ПЗРГ.xlsx». Правило
то же, что в schedule по истории (`schedule_pxg/historymode.py`): окно дебита по умолчанию 80–600 тыс. м³/сут. Нормировать нужно исходную базу
(после «Создания» или «Дополнения»); нормированную база не принимается. Schedule по нормированной базе поправку по ПЗРГ повторно не делает.

## Проверка исходников

В форме каждого модуля есть кнопка «Проверить исходники»: она читает те же поля формы, что и запуск, и показывает таблицу замечаний (ошибка, предупреждение, заметка) с местом в файле и подсказкой; результат можно выгрузить в Excel. Исходные файлы проверка не меняет и запуск не блокирует.
Общий код — `pxg_core/qc.py` (отчёт, даты, периоды, номера скважин, выбросы, единицы), проверки модулей — `pxg_base/checks/` (реестр `REGISTRY` в `__init__.py`). Пороги в `qc.SETTINGS`. Новый модуль: функция `check(values) -> Report` и строка в реестре.
Проверки только сообщают о том, что модуль сделает молча (пропустит лист, заменит текст нулём, возьмёт другой столбец); план проверок по модулям — в файлах проекта `pxg-base-qc/plan.md`.

## Разбор «Базы ГИС-контроль» (`pxg_core/gis.py`)

Ядро для будущего модуля «База ГИС» (этапы А2–А4 плана «ГИС и ГВК»; форма в интерфейсе — А10). Читает книгу, где лист = скважина, левую таблицу: шапку («Скважина №», «Алт.»), блоки по датам, интервалы, метки ГВК, примечания и статусы («не охвачена», «прихват»); правую выжимку не читает.
Даты приводятся к 1-му числу месяца (слова, сокращения, «Март1983г», опечатки, настоящие даты) с сезоном: сент.–дек. — осень, март–май — весна, прочее — «без сезона» (заметка в проверку). Расчёт: hi, hэф (Кг > 0,25, одна константа `KG_MIN`), hг эф, Кг ср.взв, этаж, ГВК а.о. = −(«до» − Алт).
Пачка определяется по заливке столбца «от» и легенде «цвет → пачка» (по умолчанию: без заливки — верхняя, 99CCFF — нижняя, FFCC99 — перемычка, FFFF99 — покрышка); у каждого листа своя легенда с причиной выбора и статусом (ок / проверить / не распознан), правится параметром `legends={лист: {цвет: пачка}}`. Один ГВК на пачку замера: второй — ошибка проверки и в расчёт не идёт. Это подсказки: решение за инженером.
`python -m pxg_core.gis файл.xlsx [--out папка]` — отчёт «сколько распознано» и сверка пересчёта с сохранёнными значениями Excel (`gis.parity`); расхождения идут списком с причиной (формула правлена вручную, порог Кг не 0,25, Кг текстом, пустые ячейки в диапазоне).

Модуль «База ГИС» (группа «ГИС и ГВК») собирает это в запуск: книга ГИС (и по желанию «Глубины_перфораций») → `ГИС_свод.xlsx` и таблицы `gis_*.parquet/csv` с версией формата (`pxg_core/gis_export.py`). Проверка исходников — `pxg_core/gis_qc.py`: наложения и дыры, Кг/Кп вне диапазона, ГВК выше кровли, скачки и ход ГВК против сезона, интервал глубже забоя, пустой лист; каждая находка с причиной, исключить можно вручную.
Легенда пачек: форма показывает таблицу «лист — цвет — пачка — сколько строк» (`/api/gis/legend`); выбор запоминается по книге и листу в `~/.pxg/gis_legend.json` (`pxg_core/gis_legend.py`) и подставляется при следующем запуске. Цвет без подтверждённой пачки в таблицы для Атласа не попадает.

## БД ГИС Беларусь (`pxg_core/gis_word.py`, `pxg_core/word_doc.py`)

Модуль «БД ГИС Беларусь» (группа «ГИС и ГВК») собирает базу из заключений ГИС в Word (.doc, .docx; папка со всеми подпапками). Word и LibreOffice не нужны: `word_doc.py` читает .doc сам (OLE2 + таблица кусков текста), LibreOffice — запасной путь, если разбор не удался.
Шапка таблицы в заключении — настоящая таблица, строки данных — текст с пробелами и табуляциями, поэтому строки ищутся по содержимому: `[метка] от - до [абс.от : абс.до] мощность Кг [ГВК глубина, ГВК абс.]`, без привязки к названиям шапки. Метка слева: горизонт (латинский индекс D2nr, V1gl1) и приписка к пачке («гл.», «песч.», «п.Н»); пустая метка наследует предыдущую, пачка = горизонт + приписка. Строка может быть слипшейся (разделитель «-----» перед меткой или после чисел, метка «str,п.2-I»/«Str 2-I»/«str.1», два столбца Кг, текст «интервал вырезки»/«не определ.», «от - до, Кг X %», «от: до»): разбор берёт числа подряд после «от - до», остальное — текст строки. Первый столбец Кг идёт в БД, второй лежит рядом («Кг второй столбец»). Пояснения («Примечание: …») уходят в «Скважины», а не в «Не распознано». Подсказка с видимой причиной: лист «Горизонты» показывает разбор каждой метки, правленный лист подаётся обратно параметром «Сопоставление меток».
Результат: `БД_ГИС_Беларусь.xlsx` (Свод, Интервалы, Замеры — их читает Атлас; Скважины — шапка заключений; Горизонты; Не распознано; Проверка) и `gis_*.csv/parquet` (общий писатель `gis_export.write_tables`). Кг в долях единицы; hэф = hi при Кг > порога (по умолчанию 0: все перечисленные интервалы, как в базе ГНТ). Заключение «с учётом отклонения от оси ствола» читается тоже: в БД идёт вариант с отклонением (по умолчанию `--depth=auto`), глубины по стволу — лист «Интервалы (по стволу)»; `--depth=md` даёт обратное. Суммы считаются по строкам, итоги заключения только сверяются (заметка). Сверка с итогами заключения («Суммарная мощность и средневзвешенный Кг»), абсолютных отметок с альтитудой и мощности с «от-до» идёт в «Проверку».

## Переносная сборка (без установки, без интернета)

Как у Газового атласа: архив со своим Python (3.13 для Windows и РЕД ОС 7.3; с tkinter) и самыми новыми версиями библиотек, которые для него существуют; Python и библиотеки, установленные на компьютере, не используются.
Распаковать и запустить `Ishodnye_dannye.bat` (Windows 10 и новее, 64-bit) или `ishodnye_dannye.sh` (Linux x86_64, glibc 2.17+: РЕД ОС 7.3 и новее). Открывается окно приложения (Windows, Edge WebView2) или браузер; отдельный сервер
запускать не нужно. `Ishodnye_dannye_console.bat` / `ishodnye_dannye_console.sh` — консольное меню модулей. Результаты — в папке `pxg_runs` рядом.

Сборка (нужны интернет и Python 3.13): `python tools/build_portable.py windows|linux` → `dist/Ishodnye_dannye_portable_*`.
CI собирает архивы по запросу: Actions → «Portable archives» → Run workflow; он же запускает программу из распакованного архива
на сгенерированных исходниках. Пакеты — последние версии из `requirements.txt` на момент сборки; зафиксировать набор можно через `pip freeze` из распакованной папки.

## Тестовые исходники

`pxg_base/testdata/flows.py` строит файлы в формате, который ждут модули расходов: папки `Отбор/<сезон>/…` и `Закачка/<год>/…`,
книги по месяцам с таблицей часового расхода и таблицей времени работы, файл периодов. В данные намеренно внесены несоответствия
«расход / время», список возвращается в манифесте. `python -m pxg_base.testdata.flows <папка>` создаёт набор вручную.
`tests/test_pxg_flows.py` запускает «Создание_базы_данных_расходов» и «Нулевые_расходы_и_несоответствия_часов» на этих данных (как из веб-интерфейса) и сверяет
число строк, фильтрацию по периодам и найденные несоответствия с манифестом. Тесты проходят на последних версиях (pandas 3) и на pandas 2.

## База давлений по замерам

Модуль `База_давлений_по_замерам` читает месячные файлы «Результаты замеров по скважинам» (две таблицы рядом, разделы «Эксплуатационные», «Наблюдательные», «Контрольные», «Поглотительные») и собирает базу с тремя замерами: Руст, Рпл, уровень жидкости. Малое Руст (ниже порога, по умолчанию 20 кгс/см²) у наблюдательных, контрольных и поглотительных скважин считается избыточным давлением и идёт в отдельный столбец. Текст в числовых ячейках («г-в», «н.д.», «кап.рем») в базу пустым, а сам текст — в «Примечании». Прежняя база дозаписывается: замер с тем же ключом (скважина, дата, горизонт) заменяется новым. Разбор формата — `pxg_core/замеры.py`.

**Еженедельные замеры (вторая строка «Еженедельные замеры»).** Файл «Итоговая таблица 2006–2026» (лист «База данных»: дата в столбце A, пары «Р устье» / «Р пл.» под заголовками «Скв.№ NNN») читает `замеры.parse_weekly`; его логика перенесена из удалённого модуля «Итоговая таблица давлений 2006–2025» без изменения разбора. Колонка «Р среднее по ПХГ» в базу не попадает: её берёт пересчёт (см. ниже).

**Слияние без дублей** (`замеры.combine`). Ключ — скважина, день, горизонт. Приоритет при совпадении ключа: 1) месячный отчёт «Результаты замеров», 2) еженедельный файл, 3) прежняя база из второй строки формы. Значение берётся из самого приоритетного источника, пустые поля дополняются из следующих. Горизонт сначала проставляется по скважине (как раньше, из последнего года), и только потом идёт слияние: иначе строка еженедельного файла без горизонта не совпала бы с месячной. Итог в сообщении: сколько дублей слито; строки без распознанной даты перечисляются в предупреждениях.

**Столбец «ГСП».** Группа берётся из строки файла, если там написано «ГСП-N» (любое написание нормируется: «ГСП 1» = «ГСП-1»). Если в строке нет, для эксплуатационных скважин берётся справочник `замеры.WELL_GROUPS` (56→ГСП-1, 83→ГСП-2, 182 и 220→ГСП-3, 237→ГСП-4, 264→ГСП-5, 437→ГСП-8, 520→ГСП-9; сверено с файлами ЭЛПРО 2022–2025). Скважина 127 в ЭЛПРО не встречается, группа для неё пустая, и она перечисляется в предупреждениях и в листе «Статистика». Колонка ГСП есть в листе «Данные» и в include «эксплуатационные» (последним столбцом после «Давление, бар»).

**Сразу пересчитать давления** (флажок «Сразу пересчитать давления» и книга со справочниками). После базы вызывается `Пересчёт_давлений.build` с настройками по умолчанию (исключённые 8, 11, 110, 122, 447; уровень как −|Нст|; include без прибавления атмосферы), среднее пластовое берётся из еженедельного файла, если он указан. Результат — «Пересчёт_давлений.xlsx» в папке результатов.

## Пересчёт давлений

Модуль `Пересчёт_давлений` заменяет Excel «ФАЙЛ_СО_ВСЕМИ_ДАВЛЕНИЯМИ»: берёт базу «База давлений по замерам» и книгу со справочниками (листы «Альтитуды» и «Перфорации»), считает плотность воды и давление на верх перфораций (глубина приведения 670 м) и выгружает include-таблицы «скважина, дата, давление (бар)»; среднее пластовое берётся готовым столбцом «Р среднее по ПХГ» из исходников по эксплуатационным (как в Excel), без файла считается по Рпл эксплуатационных скважин. Формулы: `pxg_core/пересчет_давлений.py` (проверены на значениях файла: совпадение строк, где есть альтитуда и отметка). Флажки в форме: «прибавлять 1 атм», какие include выгружать (среднее пластовое, эксплуатационные и наблюдательные с пересчётом — по умолчанию; наблюдательные без пересчёта — по желанию). Скважина без альтитуды или отметки перфорации остаётся без давления и помечается в столбце «Способ расчёта» (Excel молча считал её отметку нулём).
